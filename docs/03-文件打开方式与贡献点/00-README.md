## 一、一句话

文件树是「打开方式」机制的**第一个消费者**——好消息是**基础链路零改动**（`FoldersView.doOpenFile` 单击时早已先查宿主解析、查不到由宿主兜底）⇒ 目标达成：**任何新插件（视频播放器 …）进来，只改新插件自己，本仓一行不动**。

## 二、适配格（F1–F4 定稿与落地实绩）

| # | 格 | 定稿内容 | 落格 | 版本 | 判据 / 读数 |
|:--:|:--|:--|:--|:--|:--|
| F1 | **`openWith` 占位转正 ＝ 选择器 UI** | 右键文件 →「打开方式…」列出声明该扩展名的**全部**插件（官方＋第三方），每行「打开（仅此一次）」（不落盘）／「设为默认」（写用户覆盖表，重启仍生效）；有用户覆盖时顶部「当前默认」行 ＋「恢复自动」；空态提供「在市场搜索阅读器」。🔴 **UI 住本插件（呈现），数据来自宿主只读面（判定归壳）**——换一套文件树插件，选择器跟着走 | 第 3 波（吃壳 T2）。🔴 **第 4.5 波纠正案改判**：面板与数据组装**整体搬进宿主**（住错层纠正），本仓改为**转发**壳级 `workbench.action.openWith` | **1.0.27** → **1.0.28** | ① 多只插件声明同扩展名 ⇒ 列出全部、默认标记随覆盖表走；② **旧宿主降级**：无 `listHandlersFor` 面时命令 no-op、菜单项不出现；③ 1.0.28 读数：私有面板 3 文件 ＋ 2 测试文件删除（`grep -rn "OpenWithPanel\|open-with.css" src` = 0） |
| F2 | **注入公共 context key** | 在既有私有旗子注入点（`Menu.tsx`）增注公共键 `resourceExtname`（带点小写）＋`resourceIsFile`——第三方菜单 `when` 才能按扩展名显隐（键名进宿主保留账：**写权限 = 本插件**，读 = 任何插件） | 第 2 波（吃壳 T3） | **1.0.26** | 第三方样例 `when: "resourceExtname == '.md'"` 对 `.md` 出现 / `.txt` 不出现；根节点无文件上下文时键未定义、不误判 |
| F3 | **打开行为归一** | 原分叉：FoldersView 查不到**落兜底**、SearchView 查不到**静默不打开**——统一走宿主同一解析纯函数（有 handler 开之、无 handler 开兜底页）。宿主把 `getPluginFor` 升级为覆盖表感知后，本仓单击 / 搜索双击两个入口**零改动**即吃到同一解析 | 第 3 波（壳侧完成） | 随 **1.0.27** 生效 | 三入口（FoldersView／SearchView／`useOpenPathIntake`）行为一致；修前后对照读数成文 |
| F4 | **菜单声明对齐规范** | 本仓 `contributes.menus.fileContext` 的 18 项按壳 T5 定稿的 group/when 规范自查；命名拍板有变则同笔改 `plugin.json` | 第 2 波（吃壳 T5） | **1.0.26** 起 | 照作者文档「菜单贡献点」篇；`npm run verify` 九段全绿 |

**不变项（护栏）**：18 项右键菜单**原样**——第三方是**合并进槽位**（宿主菜单表合并 ＋ `when` 过滤），不存在替换；单击 / 双击语义（预览 / 锁定）不动；`getOpenFileFn` 桥接不动（换的只是它背后宿主侧解析器的内涵）。
